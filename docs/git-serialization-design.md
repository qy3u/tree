# Tree Git 友好序列化方案

状态：v1 及 Leaf 的 v2 扩展已实现。格式标识为 `tree-git`；不含 Leaf 的快照使用版本 `1`，含 Leaf 的快照使用版本 `2`，读取同时兼容两者。

本文定义将 Tree 的 SQLite 数据和本地附件序列化为适合 Git 管理的文件结构。目标是在 private GitHub 仓库中保存笔记的变化，使文字、格式、页面结构和计时记录的修改可以通过 diff 阅读，并能从指定版本重建本地数据库。

范围仅限序列化格式、数据组织与还原约束，不涉及推送频率、仓库配置和上传流程。

## 核心原则

采用按页面和 Block 拆分的确定性文本快照。每次导出更新同一路径下的文件，由 Git 记录新增、修改和删除；不按天生成整套副本，也不另建一份用于重放的编辑操作日志。

**数据没有变化，重复导出的文件内容必须逐字节相同。** 任意一个完整版本都应包含重建笔记数据所需的信息，无需依赖此前提交逐步重放。

这是笔记数据的可恢复序列化，不要求还原 SQLite 文件的物理布局、事务日志或进程内撤销栈。

## 文件组织

```text
tree-data/
├── format.json                 # 格式版本、稳定的笔记库 ID
├── pages/
│   └── <page-id>/
│       ├── page.json            # 标题、父页面、同层排序、图标、回收站状态
│       ├── block-order.json     # 按正文顺序排列的 Block ID
│       └── blocks/
│           ├── <block-id>.json
│           └── <block-id>.json
├── time/
│   ├── 2026-11-03.jsonl         # 当天的有效计时记录
│   └── 2026-11-04.jsonl
├── assets/
│   ├── index.json               # 附件 ID、名称、文件名与 SHA-256
│   └── <asset-id>.png           # 图片等二进制附件
└── settings/
    ├── favorites.json
    ├── session.json            # 标签页、访问记录等
    └── other.json              # 其他设置的原始键值
```

文件路径采用稳定 ID，不使用页面标题或父子页面路径。页面重命名和移动只改变元数据，不引起整个目录迁移。页面引用和 Block 引用继续使用原来的 ID。

笔记库、页面、Block、附件及计时记录的标识必须稳定，不能在每次导出时重新生成。

## 页面与正文

### 页面元数据

`page.json` 保存标题、父页面、同层排序、页面图标、回收站状态以及真实修改时间等页面信息。页面进入回收站时保留数据并改变状态，不等同于从序列化目录永久移除。

`block-order.json` 保存正文中的 Block 顺序，每行一个 ID。例如：

```json
[
  "block-a",
  "block-b",
  "block-c"
]
```

### Block 内容

每个 Block 使用独立 JSON 文件。内容与顺序分开：改字只修改对应内容文件；调整 Block 位置只改变顺序列表及确有变化的元数据。

以结构化 JSON 作为可恢复的主格式，保留 Block 类型、缩进、富文本格式、引用和计时属性。普通 Markdown 不足以完整表达这些信息。

v1 计时待办的示例（文件名就是 Block ID）：

```json
{
  "type": "timed_todo",
  "style": {
    "list": 3
  },
  "runs": [
    {
      "text": "阅读第五章",
      "attributes": {}
    }
  ],
  "timer": {
    "state": "paused",
    "elapsedNs": 750000000000
  }
}
```

`type` 使用可读类型名，`style` 保留当前原生编辑器的段落格式字段（`list: 3` 表示待办）。`style` 不重复保存 Block ID，也不保存计时历史指针；计时状态独立放在 `timer` 中。`type` 与格式字段须一致，恢复时会校验。

- 富文本以 `runs` 保存文字和对应格式，包括字体属性、颜色、行内代码及链接等。
- 代码块保存语言和按行组织的文本数组，让代码修改呈现为逐行 diff。空行、制表符、尾随空格和末尾空行均须保留，块内换行与块边界须能正确还原。
- 表格在所属 Block 中保存当前有效的行列数据，不输出编辑过程中留下的旧表格版本。
- 图片 Block 保存附件 ID、名称、显示尺寸等信息；二进制内容放在 `assets/` 中，不编码进 JSON。
- 页面与 Block 引用保存稳定目标 ID 及显示内容，不依赖标题或正文位置重新寻找目标。

逐 Block 拆分会产生较多小文件，换取更局部的修改范围，以及内容变化与顺序变化的明确区分。

### 预期 diff 范围

| 操作 | 文件变化 |
| --- | --- |
| 修改一句话 | 对应 Block 文件中的文字，以及必要的页面修改元数据 |
| 勾选普通 Todo | 对应 Block 的状态，以及必要的页面修改元数据 |
| 修改页面标题 | `page.json` 中的标题和真实修改时间 |
| 移动 Block | `block-order.json` 中的顺序，以及必要的元数据 |
| 新增 Block | 新增内容文件，顺序列表增加对应 ID |
| 删除 Block | 删除内容文件，顺序列表移除对应 ID |
| 移动页面 | 父页面或同层排序等元数据变化，内容文件路径保持不变 |
| 更换图片 | 修改附件引用，增加对应二进制文件 |
| 新增计时段 | 对应日期文件增加记录，更新所属 Block 的计时状态 |

## 按日期保存计时记录

`time/YYYY-MM-DD.jsonl` 每行保存一条有效计时记录，字段包括：

- 稳定记录标识。
- 所属页面 ID 与 Block ID。
- 起止时刻和精确耗时。
- 所属本地日期、时区与 UTC 偏移。

日期依据记录中的当地日期，不能依据导出电脑的当前时区重新分配。跨午夜的计时拆分到对应日期文件，暂停间隔不计入。

新增一段耗时通常对应新增一行。文件表示当前有效数据，因此撤销、修正等操作也可能修改或移除记录；它不是只能追加、不能修正的日志。

### 当前计时模型的适配

现有 `Body.TaskTimes` 保存用于撤销的多个不可变历史版本，Block 的 `Timer.HistoryID` 指向当前有效版本。序列化只展开当前有效记录，不把所有历史版本输出，以避免重复计时和无意义 diff。内部历史版本 ID 不作为导出计时记录的身份。

v1 计时记录的稳定标识由页面 ID、Block ID 和该段的 UTC 起始时刻生成 SHA-256，字段组合使用 JSON 字符串数组编码后计算，不采用含歧义的字符串拼接。只要记录身份不变，其 ID 不变。恢复时按任务重建当前有效历史，内部历史指针不影响再次导出的文件。

正在运行的计时保存起点、时区与此前累计值，不在导出时依据“现在”刷新累计耗时，也不因为导出而自动暂停或结算。仅有时间流逝、没有数据变化时，文本快照应保持不变。

恢复保留运行状态及原起点，之后打开应用仍按原起点继续计时。v1 不将恢复时间写入计时数据，也不自动将运行中的任务改为暂停。

累计耗时和已结束计时段必须一致；恢复时不能同时把保存的累计值与同一批记录再次相加。

## 确定性序列化规则

1. 固定使用 UTF-8、LF 换行、文件末尾换行。JSON 使用固定缩进和字段顺序，JSONL 每条记录固定为一行。
2. 中文直接输出。只做 JSON 语法需要的转义，不把普通中文全部转换为 Unicode 转义。
3. 对空值、默认值、数字和时间的输出使用统一规则，避免等价表达在不同导出中来回变化。
4. 合并相邻且格式相同的文字片段，避免编辑器内部拆分方式造成 diff；不能改变实际文字、空白或格式语义。
5. 有顺序含义的列表保留顺序；没有顺序含义的数据按稳定 ID 排序。不要依赖 map 遍历顺序。
6. 导出时不创建新身份标识，不写本次导出时间，不刷新页面真实修改时间。
7. 不输出布局坐标、渲染缓存、旧表格副本和用于撤销的过期计时历史版本。
8. 收藏、标签页和最近访问等设置单独保存，避免这些状态变化混入正文文件。
9. 附件使用稳定路径并保留原始二进制，不因导出而重新编码图片。

v1 的 JSON 缩进为两个空格。计时 JSONL 按 UTC 起始时刻、记录 ID 排序；其余无顺序含义的字典按键排序。设置文件中，收藏位于 `favorites` 字段；会话使用 `tabs`、`selected` 和 `pageVisits` 字段。`other.json` 保留其他设置的字符串值，笔记库 ID 只放在 `format.json` 中。

笔记库 ID 在本地笔记库初始化时持久化。新建和保存页面时补齐缺失的 Block ID；打开旧数据库时补齐尚未分配的 ID，保留页面真实修改时间。导出过程本身不分配这些 ID。

序列化映射应区分用户数据与可重建的内部状态。SQLite 索引、事务日志和内部并发控制状态由恢复过程建立；页面层级、回收站语义、引用、有效计时记录等不能省略。

## 重建数据库

从文本创建数据库时，保留笔记库、页面、Block 和附件的身份，恢复页面层级、正文顺序、富文本、表格、引用、设置和计时记录。

`format.json` 定义独立的序列化格式版本。遇到无法支持的版本或字段，应明确报告，不静默忽略后继续写入，以免丢失数据。

还原过程校验重复 ID、页面层级、Block 顺序与文件对应关系、附件引用和计时记录一致性。已有内容中指向已删除目标的引用保留其目标信息，不替换为同名页面。

还原到新的空目录：先验证输入，在临时目录创建数据库，再重新序列化并比对内容，成功后才发布结果。SQLite 的 `revision` 从 1 建立，真实修改时间保留。现有笔记库不被覆盖。

## 使用入口与发布约束

- 应用内：「导入与备份」→「导出 Git 文本快照…」，先保存草稿，再在所选目录内更新 `tree-data/`。
- 应用内：「从文本快照还原到新笔记库…」，选择快照目录和用于还原的空目录。
- 命令行：`Tree --export-git <快照目录> [--data-dir <源笔记库>]`。
- 命令行：`Tree --restore-git <快照目录> --data-dir <新的空目录>`。
- 打开还原结果：`Tree --data-dir <还原后的笔记库>`。

命令行导出不启动编辑窗口，也不记录新的访问时间；它读取已保存在 SQLite 中的数据。数据库中的页面、设置及附件索引通过单个查询获取同一读取快照。

导出使用专用子目录，拒绝覆盖其他笔记库或包含无关文件的目录。新文件在相邻临时目录写入、校验完成后替换旧目录；替换失败时尝试恢复旧目录。目录切换由两次重命名完成，不承诺整组文件在进程崩溃时原子切换；若恰在切换中断，旧快照可能保留在相邻 `.tree-previous-*` 目录中。无变化时不写文件。

输入拒绝符号链接、未知文件、未知字段、重复 JSON 字段、不支持的版本及无法无损还原的样式。v1 限制单文件不超过 64 MiB、快照文件不超过 100000 个、文件内容总量不超过 2 GiB；当前采用内存中校验，较大笔记库会增加内存占用。附件索引保留已入库但当前未引用的附件，未入库的孤立磁盘文件不属于快照。

## 验收标准

### 重复导出

相同数据连续导出两次，所有文件路径和字节完全一致，Git 没有新增 diff。正在运行的计时不会仅因两次导出的时间不同而产生变化。

### 往返还原

```text
数据库 → 文本 A → 新数据库 → 文本 B

A 与 B 的文件路径和内容逐字节一致
```

同时检查笔记语义，包括页面和 Block ID、富文本、代码空白、表格、图片尺寸、引用目标、回收站、设置及有效计时记录。

### 局部修改

逐项执行改字、勾选、重命名、移动、新增、删除、修改表格及计时状态变化，确认变更范围符合上述 diff 表。修改一个 Block 时，其他无关 Block 的文件不应改变。

### 格式兼容

不支持的格式或无法还原的数据必须给出明确错误，不能通过丢弃字段得到表面成功的恢复结果。

## v2：Leaf 扩展

Leaf 是有独立身份的知识单元。在页面的位置标记中保存 `leaf:<leaf-id>`，其内容保存到 `pages/<page-id>/leaves/<leaf-id>.json`。文件包含 `title`、`block_order`、以内部内容 ID 为键的 `blocks`，以及可选的 `time` 计时区间数组。此处内部内容结构是编辑和持久化细节，Leaf 在产品上仍是整体。

沿用 v1 的富文本格式与代码 `lines` 表示，内部表格保存当前内容，图片引用公共 `assets` 目录。Leaf 内的计时区间仍包含原始日期、时区、开始结束与耗时；`time` 数组的 `page` 字段在此文件内指向所属 Leaf ID，与页面级时间文件分开。读取时对其计时状态和历史总量做相同校验。

仅导出页面仍引用的 Leaf。删除 Leaf 后，移除位置标记和对应文件；移动只改页面顺序；重命名或编辑 Leaf 只改它自己的文件及页面真实修改时间。自动摘要由原文计算，折叠状态、编辑焦点和卡片高度不进入快照。

v1 快照不得包含 Leaf 位置标记。v2 拒绝缺失或重复的 Leaf、嵌套 Leaf、缺失图片、不支持的内部字段或不一致的计时区间。完整导出→还原→再导出仍要求逐字节相同。
