# Leaf：页面内的知识单元

状态：首版已实现。

[展开状态预览](leaf-expanded.png) · [收起状态预览](leaf-collapsed.png)

## 定义

Leaf 代表一段完整的知识，位于 Page 与 Block 之间。用户先创建 Leaf，再为它填写标题和内容；在所在页面内阅读与编辑，不跳转到新页面。

Leaf 有独立身份。内部采用原生富文本编辑技术以支持段落、标题、列表、代码、图片和表格，但产品上将它作为一个知识单元展示、移动和保存。不提供“将现有 Block 合成 Leaf”或“解除 Leaf”的操作。

## 创建与编辑

在页面正文输入 `/leaf`，选择 Leaf 后，在当前位置创建一个空的 Leaf 并聚焦标题。标题为空时显示“新 Leaf”占位文字。标题 Enter 进入 Leaf 正文；已有首行内容时在其前面插入空行，空首行 Backspace 返回 Leaf 标题末尾。

展开状态直接显示和编辑全部内容。正文使用现有 Markdown 快捷格式、斜杠菜单、选中文字后的格式工具、代码语言与复制、待办与计时待办、图片和表格。编辑内容随所在页面自动保存。

当前 Leaf 直属所在 Page，不创建嵌套 Leaf 或 Leaf 内的子页面。页面原有的普通正文可以与 Leaf 混排。

## 展示与折叠

白底、细浅灰边框、轻微圆角；标题行包含折叠箭头、淡色叶片图标和标题。展开高度随正文增长，使用所在页面的滚动，不添加独立滚动条。

收起时仍是一张有面积的知识卡片，保留标题，并从正文开头自动取最多 150 个 Unicode 字符作为预览；将换行和多余空白合并，超出时加省略号。预览在有限高度内显示。空内容显示占位文字。预览不要求单独编写，也不会覆盖原文。

折叠状态、编辑焦点和卡片测量高度是窗口内的显示状态，不写入知识内容，也不会产生 Git diff。

## 整体操作

页面左侧的抓手移动整个 Leaf。Leaf 的菜单提供前后插入、复制 Leaf、复制其所在位置的链接、删除 Leaf 和上下移动，不提供转换成普通段落的操作。

移动保持身份不变；复制创建新的 Leaf 身份及独立内容。删除可以撤销，移动、复制支持撤销与重做。删除位置后保留相应内容缓存，供本次编辑会话的撤销使用；搜索与导出仅处理仍在页面内的 Leaf。

## 数据与兼容性

SQLite 的页面正文增加 `leaves` 映射，键为稳定 Leaf ID，值为 `title` 与 `content`。`content` 复用正文结构以保存富文本、表格、附件引用和每日计时区间。页面编辑器使用一个 `leaf:<id>` 位置标记承载 Leaf，标记不是其内容；卡片实际高度由显示层计算。

旧笔记没有 `leaves` 字段时继续正常读取。含 Leaf 的本地正文使用 schema 2，旧版应用会拒绝读取该页，避免忽略新字段后保存而丢失内容。Leaf 标题和内容参与页面搜索。Markdown 导出将 Leaf 转为标题与正文，方便阅读；Markdown 不保留独立 Leaf 身份，完整还原使用备份或 Git 快照。

完整 ZIP 备份保留 Leaf，恢复时也重新映射其内部图片路径。Git 快照为有效 Leaf 生成独立的 `pages/<page-id>/leaves/<leaf-id>.json`，保存标题、有序内容 ID、富文本内容与计时区间。内部代码仍按行保存，图片继续使用公共二进制附件目录。修改一个 Leaf 只影响该 Leaf 文件和页面修改时间；展开/折叠不改变快照。

含 Leaf 的 Git 快照使用格式 v2；没有 Leaf 的快照继续使用 v1。读取同时兼容 v1、v2。校验缺失 Leaf、重复放置、无效内部格式、缺失图片和不一致的计时区间，避免成功恢复后丢失内容。
